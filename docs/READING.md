# Встроенное чтение и импорт RusLit

## Решение
- **Читалка**: оставлена существующая (ванильный JS, главы, шрифт, тема, закладки). Библиотеки **не добавлялись**.
  - `react-reader` (Apache-2.0): нужен React 19 и epubjs; в проекте React нет. Не подходит.
  - `foliate-js` (MIT, коммит 78914ae): рендерит EPUB/MOBI/FB2, но сам автор пишет, что API нестабилен, релизов нет, обязателен CSP, текст пришлось бы упаковывать TXT→EPUB. Для простого текста (проза, стихи) это лишний слой без пользы; источник отдаёт только TXT. Вернуться к нему имеет смысл при появлении EPUB-фонда.
  - `BookLore` (AGPL-3.0, Java + Angular + БД, Docker, переведён в режим поддержки): отдельный сервер, несовместим с Cloudflare Workers, лицензия копилефт. Не использовался.
- **Формат**: TXT напрямую, текст всегда вставляется как текст (экранирование), CSP из `public/_headers` запрещает чужие скрипты. EPUB для импорта RusLit не нужен.
- **Хранилище**: D1 (настроен). R2 в проекте не настроен и не создавался. Тексты лежат в `book_chunks` (JSON-массивы абзацев по ≤150 тыс. знаков), каталог — в `books` (только метаданные), оглавление и хеши — в `lit_files`. Ключ файла: `d1:book_chunks/<id>/<версия>`. Перенос в R2 возможен позже без изменения API.
- **Прогресс и закладки**: таблицы `reading_progress` (одна запись на пользователя и книгу, ревизия `rev`, версия текста `ver`, locator `{ch,para,p}`, процент приблизительный «≈») и `bookmarks`. Локально копия + очередь отправки (с повтором и паузами), синхронизация с задержкой 4 с, при закрытии вкладки и при возврате сети. Чужие данные недоступны: все запросы привязаны к `user_id` из подписанного initData. Свой locator вместо EPUB CFI, т.к. EPUB-движка нет.

## Источник
`d0rj/RusLit`, коммит `4509680428729da225a73a22008133660f92bb7e` (последний, 2021-07-17): 373 TXT в `prose` (269), `poems` (78), `publicism` (26) — по 16 папкам автор/жанр, 14 файлов `info.csv` (`name,year`), лицензионное заявление в README: «все произведения — общественное достояние»; тексты взяты с LitLib, Wikisource, Ilibrary «и других источников». Отдельного файла лицензии и сведений об источнике каждого файла нет. Заявление о правах не проверяет конкретное издание и не относится к Узбекистану автоматически, поэтому **всё импортируется только как черновики**.

Метаданные: название и год из `info.csv` (совпадение имени файла; 4 приблизительных совпадения помечены), автор — из справочника папок `data/ruslit/authors.json` (с проверкой по заголовку файла; конфликт помечается), жанр — по папке (проза/поэзия/публицистика), язык — русский. Ничего не выдумывается: у Лермонтова-стихов нет `info.csv`, год остаётся пустым и помечается. Описаний в источнике нет, поле пустое.

## Команды
```bash
npm install
npm run build
# 1) исходники в отдельный каталог (не в проект)
node scripts/ruslit.mjs fetch --dest /tmp/ruslit-src        # git clone --depth 1, печатает commit
# 2) dry-run: ничего не отправляется, отчёт в .ruslit/reports/
node scripts/ruslit.mjs scan --source /tmp/ruslit-src
# 3) локальный сервер с токеном импорта
npx wrangler d1 migrations apply muloqot-books --local
npx wrangler dev --port 8787 --var IMPORT_TOKEN:<случайная строка от 16 знаков>
# 4) то же с планом относительно сервера
IMPORT_TOKEN=<тот же> node scripts/ruslit.mjs import --source /tmp/ruslit-src --target local --dry-run
# 5) тестовый импорт 20 файлов
IMPORT_TOKEN=<тот же> node scripts/ruslit.mjs import --source /tmp/ruslit-src --target local --limit 20
# 6) полный импорт в локальную среду (повторный запуск безопасен; --resume продолжает прерванный)
IMPORT_TOKEN=<тот же> node scripts/ruslit.mjs import --source /tmp/ruslit-src --target local --resume
# 7) проверка: каждая глава читается обратно, хеши совпадают
IMPORT_TOKEN=<тот же> node scripts/ruslit.mjs verify --source /tmp/ruslit-src --target local
# 8) публикация проверенного списка (формат ниже)
IMPORT_TOKEN=<тот же> node scripts/ruslit.mjs publish --target local --allowlist data/ruslit/allowlist.json [--dry-run]
node scripts/ruslit.mjs unpublish --target local --ids rl...,rl...
# проверки
npm test           # 40 модульных тестов
npm run e2e        # сборка + чистая локальная D1 + API, импорт, чтение в браузере (мобильный размер)
```
`--target` допускает только localhost; для любого другого адреса нужен `--allow-remote` (после вашего разрешения). Токен читается из окружения (или `.dev.vars` для localhost) и никогда не печатается. Без секрета `IMPORT_TOKEN` на сервере импорт отвечает 503.

### Формат списка допуска
```json
{"verifiedBy":"Имя","verifiedOn":"2026-01-01",
 "rights":{"status":"public_domain","license":"…","evidenceUrl":"https://…","note":"что проверено: издание, источник"},
 "authorDeathYear":1904,"metaConfirmed":true,
 "books":[{"path":"prose/Chekhov/Ионыч.txt"},{"id":"rl…","authorDeathYear":1881}]}
```
Сервер сам проверяет: для общественного достояния — год смерти не позже «текущий − 71» (срок «жизнь + 70 лет», законодательство Узбекистана), для других оснований — ссылка или описание документа; у книг с непроверенными метаданными нужен `metaConfirmed`. Файл `data/ruslit/allowlist.json` не создан намеренно: решение о правах принимает человек. В админ-панели (Каталог) то же делается по одной книге: «Права» → «Опубликовать…».

## Что проверено в браузере и чего нет
Проверено автоматически (Chromium, 410×880): каталог, поиск, карточка, чтение главами (запросы только к `/chapter/n`), оглавление, стихи с переносами строк, закладка, синхронизация, второе устройство, обрыв сети с очередью, обновление текста источника и новая версия. **Не проверено**: настоящий Telegram WebView (iOS/Android), реальный production и реальные тексты в интерфейсе после публикации. Ручной чек-лист: открыть книгу из бота, прочитать главу, закрыть Mini App, открыть заново (позиция), сменить шрифт и тему, поставить закладку, открыть на втором устройстве, отключить интернет на 10 секунд при чтении.

## Для production (ничего из этого не выполнялось)
1. `wrangler secret put IMPORT_TOKEN` (длинная случайная строка), затем деплой: схема создаётся сама при первом запросе.
2. Бесплатный план Workers ограничивает процессорное время (≈10 мс на запрос): bootstrap с сотнями книг и импорт крупных пакетов могут упираться в лимит; импорт идёт малыми запросами (≤350 тыс. знаков), для сотен опубликованных книг рекомендуется платный план или серверная пагинация каталога.
3. Лимит D1: 500 МБ на базу (бесплатный план); 70 МБ текста помещаются.
4. `node scripts/ruslit.mjs import … --target https://<ваш-домен> --allow-remote` только после вашего разрешения; затем `verify`.
5. Составить `allowlist.json` по результатам юридической проверки конкретных изданий и выполнить `publish`.
